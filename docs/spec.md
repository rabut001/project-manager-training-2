# 仕様

プロジェクトマネージャ試験（PM）午前Ⅱの演習サイトの、現在の仕様の正本である。実装はこの文書に合わせる。仕様を変えるときは、`changes/` に案件を作り、実装の前にこの文書を更新する。

## 全体

- IPA が公開している PM 午前Ⅱを、1問ずつ解く静的サイト。公開先は GitHub Pages、公開パスは `/project-manager-training-2/`。
- 収録は 17 回（平成21〜31年度春期、平成23年度特別、令和2年度10月、令和3〜7年度秋期）、各25問。
- 1問の流れは、問題画像の表示、ア〜エの選択、結果確認、正誤・正答・解説の表示。選択済みで未確認の問は、一括採点でもまとめて確認できる。未選択は採点しない。
- 問題は切り出した画像で表示する。問題文のテキストはデータに持つが、画面には出さない。ブラウザで PDF は描画しない。
- 解説は公式資料にない。データ作成時に書いて JSON に保存し、実行時には生成しない。画面に「IPA の公式解説ではない」と表示する。
- 進捗はブラウザの `localStorage` だけ。アカウントや端末間の同期はしない。
- レスポンシブ。携帯と PC のブラウザで、同じ画面と同じ操作ができる。PC ではキー操作もできる。
- 配色は OS の設定に従い、ライトとダークを切り替える。切り替えボタンは置かない。問題画像は白地のまま表示する。
- 作らないもの: ランダム出題、苦手だけの復習、分野タグ、一覧の進捗表示、解説の肢ごとの表示。

## 問題データ

`content/` に置く。アプリは開発サーバとビルドの両方で、このフォルダを `/project-manager-training-2/content/` として配信する。

- `content/index.json` … 収録する回の配列。要素は `id` と `title`。新しい順。
- `content/<id>/exam.json` … 回の `id`、`title`、`questions`。
- `content/<id>/q01.webp` 〜 `q25.webp` … 問題画像。問の途中で切れない。図は画像の中に残す。
- `content/sources.json` … 取得元の URL、取得日、SHA-256。サイトに載ってよい。

回の `id` は `西暦-和暦-時期`（例: `2025-r07-aki`、`2019-h31-haru`、`2020-r02-oct`、`2011-h23-toku`）。

問の項目:

| 項目 | 内容 |
| --- | --- |
| `no` | 1〜25 |
| `answer` | ア、イ、ウ、エ。IPA の解答例から取る。解答例に注記があり正解が無い問（平成28年度春期 問2「誤りにより問題として成立しない」）は `null` |
| `answerNote` | `answer` が `null` のときだけ持つ。解答例の注記の文 |
| `image` | `content/` からの相対パス（例: `2025-r07-aki/q01.webp`） |
| `stem` | 設問文。表がある問は、表も Markdown の表で書く |
| `choices` | `ア`〜`エ` をキーにした肢の本文。肢が表のときは Markdown の表で書く |
| `visuals` | 文章だけでは表せない要素。`figure`（図・グラフ）、`table`（表）、`image`（その他の画像）。該当がなければ空配列 |
| `explanation` | 学習用の解説。`answer` と矛盾しない。「<正解>が正解」を含む（`answer` が `null` の問を除く） |

画面が使うのは `no`、`answer`、`answerNote`、`image`、`explanation` だけである。

`answer` が `null` の問は、どの肢を選んでも正解として数える。結果では正答を `—` とし、「IPA の解答例の注記: {answerNote}どの肢を選んでも正解として数えます。」を解説の前に出す。

## 回の一覧

- 入口。URL は `/project-manager-training-2/`。
- `index.json` の回を新しい順に並べ、各回は `title` だけを出す。正解数や正解率は出さない。
- 下に出典として [IPA の過去問題](https://www.ipa.go.jp/shiken/mondai-kaiotu/index.html) へのリンクを置く。
- 各回は指で押せる大きさにする。幅が広いときは本文を画面いっぱいに引き伸ばさない。

## URL

- 選んだ回は `/project-manager-training-2/<id>/`。問の移動では URL を変えない。ルーティング用のライブラリは使わない。
- 再読み込みや、ブラウザの戻る・進むで、その画面に戻る。
- 存在しない回のパスでは「この回はありません。」と一覧へ戻るリンクを出す。
- ビルド成果物には同じアプリを `404.html` としても置き、公開先で一覧以外のパスを直接開いても、このアプリが開く。

## 演習画面

回ごとに作り分けない。1枚の画面で、問を替えると中身が入れ替わる。一括採点とクリアの前だけ、確認のダイアログが重なる。一覧へ戻っても、その回の保存は消さない。

上から次の順に置く。

1. **一覧へ戻る**。
2. **回の `title` と正解数**。確認済みの問のうちの正解数と正解率（例: `8/10（80%）`）。1問も確認していないときは `—`。
3. **1〜25の番号**。押すとその問へ移る。
   - 開いている問は濃い青地に白で反転する。
   - 確認済みは、開いている問を除き、正解なら薄い緑、誤答なら薄い赤のボタンにし、数字の下に ○ / × を出す。
   - 選択済みで未確認は、開いていないとき枠を濃い金にする。印は出さない。
   - チェックした問は、数字の下に太いチェック（線の図形。文字の ✓ は使わない）を出す。○ × があるときは ○ × が左、チェックが右。チェックは黒、開いている問では白で描く。
   - 番号は幅も高さも `2.75rem`。印の有無で大きさを変えない。狭い幅では折り返す。
   - 1〜3 は、問題画像をスクロールしても画面上部に残す。
4. **問題画像**。表示幅に合わせて縮め、はみ出した分はこの部分だけ縦にスクロールする。スクロールバーは出さない。画像の上の右端にチェックボックスを置く。画像の幅を削らず、文字や図に重ねない。画像をスクロールしても位置は残る。
5. **ア・イ・ウ・エ**。結果確認前は選び直せる。
6. **結果を確認**。選択があるときだけ押せる。押すと選択を固定し、正誤・正答・解説と「IPA の公式解説ではない」を出す。
7. **前へ・次へ**。問1では前へ、問25では次へを押せない。
8. **一括採点**。選択済みで未確認の問があるときだけ押せる。確認ダイアログで実行すると、それらを確認済みにする。未選択は採点せず、正解率の分母にも入れない。開いている問が対象なら、その場で結果を出す。
9. **回答をすべてクリア**。確認ダイアログで実行すると、その回の解答と開いている問番号を消して問1の未選択に戻る。チェックは残す。ほかの回は消さない。確認文は「{title}の確認済みの解答と、まだ確認していない選択を消して、問1に戻ります。チェックはそのまま残します。」
10. **フッター**。PC（細かく指せるポインタの端末）だけに「キー操作: 1〜4 選択、Enter 確認、← → 前後の問」を出す。その下に出典の [IPA の過去問題](https://www.ipa.go.jp/shiken/mondai-kaiotu/index.html) へのリンク。

5〜10 は、はみ出した分だけ縦にスクロールし、スクロールバーは出さない。別の問へ移ったときは、問題画像と下部のスクロールを先頭に戻す。

ページ全体は横にはみ出さない。ボタン、リンク、チェックボックスは指で押せる大きさ（最小 `2.75rem`）にする。幅が広いときは、本文を `42rem` までに抑える。

### 問の状態

| 状態 | 選択 | 結果 |
| --- | --- | --- |
| 未選択 | ア〜エを押せる | 「結果を確認」は押せない |
| 選択済み・未確認 | 選んだ肢が分かり、変えられる | 正誤は出さない |
| 確認済み | 固定 | 正誤、正答、解説、公式解説ではない旨 |

チェックはこれとは別で、どの状態でも付け外しでき、選択や正誤を変えない。

### キー操作

ダイアログが開いているとき、Alt・Ctrl・Meta を押しているとき、日本語入力の変換中は、何もしない。

| キー | 動作 |
| --- | --- |
| `1`〜`4` | ア〜エを選ぶ（確認済みの問では何もしない） |
| `Enter` | 結果を確認。フォーカスがア〜エのボタンにあるか、どこにもないときだけ。ほかのボタンにフォーカスがあるときは、そのボタンを押す |
| `←` / `→` | 前へ / 次へ（端の問では何もしない） |

### 読み上げ

- 番号ボタンは「問3、チェック済み、選択済み、未確認」のように、問番号、チェックの有無、状態（未選択／選択済み、未確認／正解／誤答）を読む。○ × とチェックの図形は読ませない。
- チェックボックスは「問Nをチェック」と読ませる。見た目の文言は付けない。

## 進捗の保存

`localStorage` のキーは `pm-am2:<id>`。値は次の形。

```json
{
  "currentNo": 3,
  "answers": { "1": { "choice": "イ", "confirmed": true } },
  "checked": [3, 14]
}
```

- `answers` は、結果確認した解答（`confirmed: true`）と、まだ確認していない選択。再読み込み後も、確認済みの選択は固定のまま。
- `checked` は昇順・重複なし。読み込み時、配列でなければ空、整数でない値やその回に無い番号は捨てる。
- 番号や前へ・次へで移るとき、移動先が未確認なら保存してある選択を戻し、確認済みなら結果を出した状態で開く。
- 一括採点はチェックを変えない。クリアは `answers` を空、`currentNo` を 1 にし、`checked` は残して同じキーに保存する。

## 公開

- `main` への push で、GitHub Actions がデータ検証とビルドを行い、GitHub Pages へ載せる。手動でも実行できる。
- 成果物は `app/dist`。ビルド時に `content/` を `dist/content/` へ複製し、`index.html` を `404.html` としても置く。
- IPA の PDF はリポジトリにも成果物にも入れない。
