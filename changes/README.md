# 改修案件

アプリを作る・直すときの管理資料を、案件ごとのフォルダに置く。サイトには載せない。

現在の仕様の正本は [docs/spec.md](../docs/spec.md) である。このフォルダの文書は、その時点の判断と作業の記録であり、仕様の参照先にしない。

## 進め方

画面、操作、保存、問題データ、公開のしかたを変える依頼を受けたら、実装に入る前に案件フォルダを作り、[_template.md](_template.md) を写して `README.md` を書く。利用者から文書の作成を指示されなくても行う。質問への回答や、仕様を変えない調査だけでは作らない。

- フォルダ名は `NNNN-短い英語の名前`。`NNNN` は既存の最大番号に 1 を足した 4 桁。
- 製品の仕様を変えるときは、実装の前に `docs/spec.md` を更新する。
- レビューで出た直しは、その案件のフォルダで扱う。完了した案件への別の依頼は、新しい番号にする。
- 状況が「完了」になった案件のフォルダは、以後修正しない。

## 状況

| 状況 | 意味 |
| --- | --- |
| 文書作成 | 文書を書いていて、実装には入っていない |
| 着手 | 実装に入っている |
| レビュー待ち | 実装が終わり、利用者のレビューを待っている |
| 確認中 | レビューを通過し、確認を進めている |
| 完了 | 確認が終わった |
